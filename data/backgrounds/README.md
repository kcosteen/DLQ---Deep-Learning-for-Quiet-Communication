# Background textures — `data/backgrounds/`

Backgrounds consumed by `src.augment.BackgroundReplacer` (issue #10) for the
**structural** augmentation that most directly fights *"one signer in one room"*:
the MediaPipe-segmented hand is composited over a random image from this folder,
so the model learns the hand shape, not the room behind it.

## How it's used

`BackgroundReplacer(backgrounds_dir)` globs this folder (non-recursively) for
`*.jpg`, `*.jpeg`, `*.png`. On each call it picks one at random, segments the hand
with `models/selfie_segmenter.tflite`, and pastes the hand over that background at
the input's native resolution. The shared `src/crop.py` contract
(`resize_square` + `normalize_chw`) still runs **after**, so train/serve parity is
untouched.

It is wired in **train-only** and probabilistically:

- `build_transforms(train=True, backgrounds_dir="data/backgrounds")` — applies bg
  replacement ~50% of the time, *before* the Albumentations ops and the contract.
- `python -m src.train --backgrounds data/backgrounds ...` — threads it through the
  training run (the val/serve path never sees it).

Graceful fallbacks: an empty folder, or an unreadable image, returns the input
unchanged (this is also what lets the unit tests run without mediapipe).

## What's committed here

A handful of **tiny synthetic** textures (`sample_*.png`, ~96×96, a few KB each)
generated by `generate_samples.py`. They exist so the demo and the ablation work
out of the box with nothing to download:

```bash
python -m src.augment --image <a training image> --backgrounds data/backgrounds \
    --out docs/figures/augment_bg_preview.png
```

Regenerate them with:

```bash
python data/backgrounds/generate_samples.py
```

## Populating a real set

For an actual training run, replace the synthetic samples with **varied
photographic scenes** — indoor (rooms, walls, desks, kitchens) and outdoor
(streets, foliage, sky), varied lighting and colour. A few hundred is plenty.
Just drop the image files into this folder:

```bash
cp ~/my_scenes/*.jpg data/backgrounds/
```

Those user-added images are **git-ignored** by default (see `.gitignore`): a real
set is large, so — like `data/raw/` and `data/cache_crops/` — it stays local and
is never committed. Only `sample_*.png`, this README, and the generator are tracked.
